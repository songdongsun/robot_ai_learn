本篇记录本次关于训练流程、数据来源、Actor／Critic／AMP、参数更新，以及“下一步采样”和“下一轮采样”的讨论。以从头训练单机器人搬箱子策略为例，保留完整图解和解释。

## 1. 三个网络分别负责什么？

我们就以 **CooHOI 中“从头训练一个单机器人搬箱子的策略”**为例，把数据从哪里来、三个网络分别干什么、参数怎么更新，以及最终输出什么串起来。

先记住三个角色：

| 网络 | 它要回答的问题 |
|---|---|
| **Actor 策略网络** | 我现在应该做什么动作？ |
| **Critic 价值网络** | 从当前状态继续做下去，预计能获得多少回报？ |
| **AMP 判别器** | 机器人产生的运动，像不像参考动作？ |

**三个网络都参与训练，但直接决定机器人动作的是 Actor。**

## 3. 第一轮还没有训练数据，怎么开始？

**先由环境给出状态，再由尚未训练好的 Actor 尝试动作。**

```text
初始化环境                         初始化 Actor
机器人站在某个位置                 参数按初始化规则设置
箱子摆在某个位置                   还不会搬箱子
目标位置已设定                           │
       │                                 │
       ▼                                 │
第一份观测 obs₀ ──────────────────────────┘
                         │
                         ▼
                    输出动作 a₀
```

“不会搬箱子”不等于“不能输出数字”。

就像未训练的 YOLO 也能输出预测框，只是通常不准确。未训练的 Actor 也能输出动作，只是动作可能没用。

另外，**从头训练指网络参数从头学习，不代表环境没有任何先验**。机器人结构、控制器、任务规则、参考动作和初始状态设置，都是我们已经提供的条件。

### 初始权重和参考动作不是一回事

我们此前的小规模训练没有加载 `SingleAgent.pth`，配置中的 `load_checkpoint` 为 `false`，因此从初始化网络参数开始。

**没有加载预训练权重，不等于网络没有权重。** 网络创建时已经具有初始化参数，只是这些参数尚未学会任务。

| 内容 | 含义 |
|---|---|
| 网络结构 | 定义输入如何经过网络计算输出 |
| 初始化参数 | 尚未学习任务的参数起点 |
| `.pth` 检查点 | 保存已经训练得到的参数等信息 |
| `--motion_file` 参考动作 | 提供运动示例，不是 Actor 的初始权重 |

## 4. Actor 到底输出什么？

先看它的输入：

```text
obs：当前观测向量
│
├─ 身体姿态相关信息
├─ 关节状态相关信息
├─ 运动速度相关信息
└─ 箱子、目标等任务相关信息
```

具体字段由任务代码决定。当前主要使用仿真状态，并不是相机图片。

网络的基本计算可以理解为：

```text
观测 obs
   │
   ▼
输入处理、归一化
   │
   ▼
MLP 隐藏层：1024
   │
   ▼
MLP 隐藏层：512
   │
   ▼
动作分布的均值 μ
```

当前配置使用固定、不学习的动作分布标准差。训练时，可以围绕均值采样动作：

```text
Actor 给出的动作均值
          │
          ├─ 采样动作 A → 试试看
          ├─ 采样动作 B → 试试看
          └─ 采样动作 C → 试试看
```

**探索让策略有机会尝试不同动作，观察哪些结果更好。**

输出是一个动作向量：

```text
action = [a₁, a₂, …, aₙ]
```

它不是“抬箱子”这种文字指令，也还不是直接施加的力矩。

## 5. 数字动作怎么变成真实的仿真运动？

这段连接了你前面学的控制和动力学：

```text
Actor 输出 action
        │
        ▼
关节目标映射
q_d = offset + scale × action
        │
        ▼
得到目标关节角度 q_d
        │
        ├──────────────┐
        ▼              ▼
     目标角度      实际角度、速度
        │              │
        └──────┬───────┘
               ▼
            PD 驱动
               │
               ▼
           关节力矩 τ
               │
               ▼
          物理仿真计算
质量、惯性、重力、接触、摩擦……
               │
               ▼
       新的机器人与箱子状态
```

这里的 `scale × action` 是各分量分别相乘。

这几个模块职责不同：

- **Actor**：选择控制目标。
- **PD**：根据误差追踪目标。
- **动力学仿真**：计算施加控制后实际发生什么。

例如，Actor 想让某个关节转动，并不意味着它瞬间就到达目标角度。它需要在力矩和物理约束下运动。

## 6. 执行一次动作，怎样产生一条经验？

假设执行前是 `obs₀`：

```text
obs₀ ──Actor──→ a₀ ──环境执行──→ obs₁
                              │
                              ├─ 任务奖励
                              ├─ 是否结束
                              └─ AMP 运动特征
```

程序保存：

```text
我之前看到了什么？         obs₀
我选择了什么动作？         a₀
当时选择该动作的概率？     后续 PPO 更新要用
当时预计能获得多少回报？   Critic 的价值估计
执行后变成什么样？         obs₁
任务完成得怎么样？         任务奖励
回合是否结束？             done
身体实际怎样运动？         AMP 运动特征
```

接着继续：

```text
obs₁ → a₁ → obs₂
obs₂ → a₂ → obs₃
……
```

结束的环境会被重置，继续产生经验。

我们的小测试配置：

```text
16 个并行环境
每个环境采样 32 步
        │
        ▼
一轮得到 512 条交互记录
```

**这段采样期间，网络在计算输出，但尚未进行本轮的优化器更新。**

## 7. 参考动作怎么与这批经验联系起来？

参考动作主要走的是 AMP 这条链。

先把两类运动都转换成可供判别器处理的特征：

```text
提前准备的参考运动                策略实际生成的运动
        │                               │
        ▼                               ▼
参考运动特征                      生成运动特征
        │                               │
        └────────────┬──────────────────┘
                     ▼
                AMP 判别器
```

要区分判别器的两种用途。

### 用途 A：给策略的运动产生模仿奖励

```text
策略生成的运动特征
        │
        ▼
当前 AMP 判别器
        │
        ▼
判断它有多像参考运动
        │
        ▼
转换成模仿奖励
```

这不是对着参考文件逐帧检查：

```text
“参考第 10 帧抬手，所以你第 10 帧必须抬手。”
```

它学习的是参考运动的特征，并评价策略运动是否具有类似特征。

### 用途 B：训练判别器自己

```text
参考运动 → 标记为参考样本 ──┐
                           ├─ 计算判别损失 → 更新判别器
生成运动 → 标记为生成样本 ──┘
```

生成样本既包含当前采样的运动，也可以包含历史生成运动。

**判别器不是固定的老师。它自己也在学习，所以第一轮的模仿评价还不可靠，会随着训练一起变化。**

### 两路数据应当怎样称呼？

| 数据 | 来源 | 是否固定 |
|---|---|---|
| 参考动作数据 | 预先准备的运动数据 | 数据源通常固定，训练中从中采样 |
| 策略交互数据 | 当前策略在仿真中的尝试 | 每轮采集，会随着策略与环境状态变化 |

**参考动作也参与训练，主要用于训练判别器。** 所以不是“参考数据不属于训练数据”，而是两路数据承担不同职责。

Actor 不是直接与参考动作逐项对答案，而是通过模仿奖励间接受到参考运动的引导。

## 8. 为什么还需要任务奖励？

因为“动作像人”和“把事情做成”不是一回事。

```text
机器人原地自然地活动
        │
        ├─ 运动特征可能像参考
        └─ 但没有完成搬箱子
```

所以需要另一条评价：

```text
机器人与箱子的新状态
        │
        ▼
任务奖励函数
        │
        ├─ 是否接近合适的位置？
        ├─ 手是否接近搬运点？
        └─ 箱子位置、朝向等是否朝目标改善？
```

当前代码最终组合：

```text
任务奖励 × 0.5
       +
模仿奖励 × 0.5
       │
       ▼
策略学习使用的奖励
```

两个权重相同，不表示两种奖励数值一定一样大。

还要注意：

**奖励是我们写出来的评分规则，并不是系统天然理解“正确搬箱子”。** 如果规则有漏洞，策略可能学会刷分，却没有真正完成预期任务。

## 9. 有了奖励，为什么还需要 Critic？

因为单步奖励不能完整说明一个动作的价值。

比如：

```text
弯腰伸手
   ↓
当下箱子没有移动
   ↓
但为后面抓住、抬起箱子创造了条件
```

如果只看当下“箱子移动了多少”，可能低估这个动作。

Critic 用于估计：

> 从当前状态开始，按照当前策略继续执行，预计能得到多少未来累计奖励？

```text
当前观测 obs
      │
      ▼
    Critic
      │
      ▼
价值估计 V(obs)
```

然后结合实际采样到的奖励、后续价值估计，计算**优势**。

直观地说：

```text
优势 ≈ 这次尝试带来的回报 − 原先预期的回报
```

这里是帮助理解的概括；实际代码会结合多步信息和折扣进行估计。

举一个只用于理解的数字例子：

```text
原先预计能得到 5 分
这次经验估计能得到 8 分
            ↓
优势为正：比预期好

原先预计能得到 5 分
这次经验估计只能得到 2 分
            ↓
优势为负：比预期差
```

**Critic 不负责输出控制动作，也不直接修改奖励，它帮助判断哪些动作比预期更值得鼓励。**

## 10. PPO 怎样改进 Actor？

PPO 更新时，会重新把采样时的观测输入网络，并考察**当时实际执行的动作**。

```text
采样时的观测 obs
        │
        ▼
当前 Actor
        │
        ▼
重新计算“选择当时那个动作”的概率
        │
        ├─ 与采样时记录的旧概率比较
        └─ 结合该动作的优势
```

基本方向是：

```text
优势为正
    ↓
倾向于提高这类动作的选择概率

优势为负
    ↓
倾向于降低这类动作的选择概率
```

但一次更新不能太激进。PPO 的裁剪目标会限制某些过大的概率变化对优化目标的贡献，帮助训练保持稳定。

**它不是把某次好动作写进固定动作表，而是调整网络参数，让类似状态下的动作分布发生变化。**

## 11. 三个网络如何真正更新参数？

在代码的 `calc_gradients()` 中，形成一个组合损失：

```text
Actor 损失 ──────────┐
Critic 损失 ─────────┤
AMP 判别器损失 ──────┼─→ 总损失
动作边界等其他项 ────┘
                         │
                         ▼
                     反向传播
                         │
                         ▼
                 计算各网络参数的梯度
                         │
                         ▼
                    优化器更新
```

对应的关键代码：

```python
self.scaler.scale(loss).backward()
self.scaler.step(self.optimizer)
self.scaler.update()
```

其中各部分主要负责：

| 网络 | 学习依据 | 更新目标 |
|---|---|---|
| Actor | 观测、执行动作、旧概率、优势 | 改善动作选择 |
| Critic | 观测、回报目标 | 改善价值估计 |
| 判别器 | 参考运动与生成运动 | 改善对两类运动的区分 |

**这里不是通过“力矩 → 物理仿真 → 奖励”这整条链反向求导。**

当前实现中：

```text
仿真交互：生成经验，不反向传播
网络更新：用经验构造损失，在网络里反向传播
```

这也是采样时使用 `torch.no_grad()` 的原因。

## 12. 第二轮开始，哪些东西变了？

```text
第一轮
初始策略 → 产生经验 A → 更新网络
                              │
                              ▼
第二轮
新版策略 → 产生经验 B → 更新网络
                              │
                              ▼
第三轮
新版策略 → 产生经验 C → 更新网络
```

| 内容 | 后续轮次的情况 |
|---|---|
| 机器人模型、任务规则 | 通常保持不变 |
| 参考动作数据源 | 通常保持不变，但会重新抽样 |
| Actor 参数 | 持续更新 |
| Critic 参数 | 持续更新 |
| AMP 判别器参数 | 持续更新 |
| 策略交互经验 | 持续产生新数据 |

当前 PPO 的策略更新主要使用新采集的一批经验，并在这批数据上进行若干遍更新；**AMP 判别器还会使用历史生成运动缓冲区。** 不要把两者理解成所有历史数据都长期混在一起反复训练 Actor。

## 13. 训练结束后，为什么推理简单了？

训练期间要回答：

```text
怎么动？
做得好不好？
比预期好多少？
像不像参考运动？
参数应该怎么改？
```

训练完成后，执行任务主要只需要：

```text
加载训练好的 Actor 和所需归一化参数
                    │
                    ▼
观测 → Actor → 动作 → PD → 仿真运动
 ↑                              │
 └──────── 新观测 ───────────────┘
```

**产生动作时不需要 Critic 或 AMP 判别器参与决策，也不需要边运行边更新参数。** 程序仍可能计算奖励用于评估。

检查点 `.pth` 保存的是参数等训练状态；它本身不是一段预先录好的搬箱子动作。

你现在可以把整套原理压缩成下面这张图来记：

```text
参考运动 ──→ 判别器学习 ──→ “像不像”的奖励 ──┐
                                            │
任务规则 ────────────────→ “做得好不好”的奖励 ─┤
                                            ▼
Actor → 动作 → 仿真 → 新经验 ─────────→ 评价这批尝试
  ▲                                         │
  │                  Critic ──→ 提供价值估计 ┤
  │                                         ▼
  └──────────── PPO 根据优势更新策略 ─────────┘
```

## 14. “下一步继续采样”和“下一轮采样”有什么区别？

**“下一步”是同一轮里，继续执行一个动作；“下一轮”是这批数据训练完后，用更新过的网络重新采集一批数据。**

结合我们的小测试配置：

```text
第 1 轮：使用第 1 版策略
│
├─ 第 1 步：obs₀ → 动作 → obs₁，保存经验
├─ 第 2 步：obs₁ → 动作 → obs₂，保存经验  ← 下一步继续采样
├─ 第 3 步：obs₂ → 动作 → obs₃，保存经验
│  ……
└─ 第 32 步：执行动作，保存经验
          │
          ▼
16 个环境 × 32 步 = 512 条交互记录
          │
          ▼
用这批数据训练，更新网络参数
          │
          ▼
第 2 轮：使用第 2 版策略                 ← 下一轮采样
│
├─ 第 1 步：执行动作，保存经验
├─ 第 2 步：执行动作，保存经验
│  ……
└─ 第 32 步
          │
          ▼
再用新数据更新网络
```

| 区别 | 下一步采样 | 下一轮采样 |
|---|---|---|
| 发生在什么时候？ | 当前批次还没收集完 | 上一批数据已经完成训练更新 |
| Actor 权重更新了吗？ | 没有进行优化器更新 | 已经更新 |
| 目的是什么？ | 每个环境再收集一条经验 | 用新版策略收集下一批经验 |

还有一个容易混淆的概念：**“一轮训练”不等于“一回合搬箱子”。**

```text
步 step：执行一次动作、推进环境。

回合 episode：从环境重置开始，到成功、失败或超时等结束条件。

训练轮次：采集一批经验，再用它更新网络。
```

这里列的是回合结束条件的通用类别，具体任务是否在成功时立即结束，以任务的重置代码为准。

因此：

- 采样过程中摔倒了，可以重置该环境，继续凑齐本轮数据。
- 采满 32 步但机器人还没结束回合，也可以先更新网络，下一轮继续当前环境状态，**不必因为换了一轮就重置机器人**。

对应代码：

```python
# 下一步：仍然在 play_steps() 的循环里
for n in range(self.horizon_length):
    ...
```

```python
# 下一轮：外层循环再次调用 train_epoch()
while True:
    epoch_num = self.update_epoch()
    train_info = self.train_epoch()
```

**记住这个边界：采样一步接一步，是在攒经验；训练一轮接一轮，是在“攒经验 → 更新网络 → 再攒经验”。**

## 15. 与 YOLO 训练对照

```text
YOLO 常规训练：
预先准备的数据集 → 反复取批次 → 更新网络
（取样顺序、数据增强等仍会变化）

CooHOI 的 PPO 策略训练：
当前策略 → 与环境交互生成一批数据 → 更新策略
    ↑__________________________________|
```

| 环节 | YOLO 检测训练 | CooHOI 策略训练 |
|---|---|---|
| 数据来源 | 图片与标注 | 交互经验，加上 AMP 的参考运动 |
| 网络输出 | 检测框与类别等 | 动作分布及动作 |
| 学习依据 | 预测与标注的差异 | 奖励、优势、回报目标及判别损失等 |
| 参数更新 | 损失、反向传播、优化器 | 同样使用损失、反向传播、优化器 |
| 后续数据 | 继续读取准备好的数据集 | 更新策略后产生新的经验 |
| 保存成果 | 常见为 `.pt` | 当前项目使用 `.pth` |

`.pt` 与 `.pth` 的后缀不是两种学习方法的本质区别。关键是模型、保存内容及对应加载代码。
