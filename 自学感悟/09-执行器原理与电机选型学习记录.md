### 1.1 执行器不一定只是一台电机

```text
                   电源
                    ↓
目标角度 → 控制电路 → 功率驱动 → 电机 → 减速机 → 关节
              ↑                              │
              └────── 编码器位置反馈 ─────────┘
```

这表示功能关系，不同产品的编码器实际安装位置可能不同。

- 控制电路：比较目标与反馈，计算控制输出。
- 功率驱动：控制电源向电机提供的电流。
- 电机：把电能转换成机械运动。
- 减速机：降低转速、提高输出转矩，同时存在损耗。
- 编码器：提供位置测量，用于反馈。

电机 ID 只帮助程序找到设备；控制电路、驱动器和电机才负责执行动作。

### 1.2 为什么有刷和无刷电机需要换向

电流产生磁场，磁场相互作用产生转矩。为持续按所需方向转动，需要在合适时刻改变线圈通电状态。

```text
有刷电机：电刷与换向器完成机械换向
无刷电机：驱动电路完成电子换向
```

“无刷”不是不需要控制电流，而是去掉机械接触换向，改用电子换向。

### 1.3 文档中不能直接作为工程结论的简化

| 原文表达 | 本次讨论中的澄清 |
| --- | --- |
| 将伺服与有刷、步进直接并列 | 伺服强调反馈控制，与电机结构分类不是同一维度 |
| 电机必须经过 H 桥 | H 桥常用于有刷直流电机双向驱动，三相无刷使用相应三相驱动电路 |
| 电机不能直接带负载 | 存在直驱方案，是否需要减速机由任务与结构决定 |
| 步进开环即可精确定位 | 依赖没有丢步等条件，开环本身不能确认实际到位 |
| 特性曲线下方就是安全区 | 还要检查连续工作区、温升、电流和工作周期 |

原文小车代码的 `Total_Force * radius` 首先得到车轮侧的总牵引转矩需求。存在多个驱动轮时需要分配，存在减速机构时需要换算，不能直接解释为每台电机轴所需转矩。

## 2 追问：程序已经知道“要怎么动”，这个目标怎么来的？

程序不是天然知道目标，而是接收人的输入，或由上层算法产生目标。

### 2.1 人直接指定关节目标

```python
target_angle = 30  # 希望某个关节到达30°，仅作概念示例
```

```text
人指定肘关节到 30°
        ↓
程序按设备协议转换、发送目标
        ↓
控制器读取反馈并驱动电机
        ↓
关节接近目标位置
```

“到 30°”只规定终点，速度和加减速过程还需要规划，可以由应用或控制器内部功能完成。

### 2.2 遥操作的目标来自人的动作

```text
人移动主臂
    ↓
读取主臂关节位置
    ↓ 校准与映射
形成从臂目标
    ↓
从臂跟随，目标持续更新
```

### 2.3 末端目标通过计算变成关节目标

```text
希望夹爪到杯子上方并朝下
        ↓ 确定目标位置与朝向
末端目标位姿
        ↓ 逆运动学
各关节目标角度
        ↓ 轨迹规划
沿途每时刻的角度、速度、加速度
        ↓ 控制与驱动
实际机械臂运动
```

| 层次 | 举例 | 负责环节 |
| --- | --- | --- |
| 动到哪里 | 肘关节从 0° 到 30° | 人、遥操作输入或上层算法 |
| 沿途怎么走 | 平滑加速，再减速到位 | 轨迹规划或控制器内部规划 |
| 实际怎么带动 | 调节电流产生所需转矩 | 控制器、驱动器、电机 |

执行器选型主要检查第三层的硬件能力。程序能正确发送“抬起物体”的目标，不代表转矩不足的电机就能实现它。

## 3 选型前的两个直观例子

### 3.1 只算末端物体的静态负载

假设杆水平，忽略杆重，末端 1 kg 物体距关节轴 0.2 m：

$$
F=mg=1\times9.81=9.81\ \mathrm N
$$

$$
\tau=Fr=9.81\times0.2=1.962\ \mathrm{N\cdot m}
$$

这是简化情况下静止保持所需的关节输出转矩。实际还需考虑杆重、加速、摩擦、传动、持续发热及速度要求。

### 3.2 减速机怎样改变转速和转矩

定义减速比与效率：

$$
i=\frac{\omega_{\mathrm{电机}}}{\omega_{\mathrm{输出}}},\qquad
\omega_{\mathrm{输出}}=\frac{\omega_{\mathrm{电机}}}{i},\qquad
\tau_{\mathrm{输出}}\approx\eta i\tau_{\mathrm{电机}}
$$

例如电机转速 1000 rpm、转矩 0.1 N·m，减速比 20，假设效率 80%：

$$
n_{\mathrm{输出}}=1000/20=50\ \mathrm{rpm}
$$

$$
\tau_{\mathrm{输出}}\approx0.8\times20\times0.1=1.6\ \mathrm{N\cdot m}
$$

减速机用速度换取转矩，不会凭空增加功率。讨论任何转矩、转速之前，要说明是在电机轴还是减速机输出轴。

## 4 最后一轮问答原文：电机的选型怎么选？

以下问题及回答按本次聊天原文收录，未压缩计算、删减步骤或改写措辞。

### 用户问题原文

电机的选型怎么选？

### 回答原文

**电机选型，就是先算“负载需要多大的转矩、转多快、持续多久”，再找能满足这些要求的电机、减速机和驱动器。**

不是先挑一个功率大的电机，再试试能不能带动。

```text
任务要求
带多重？力臂多长？转多快？加速多快？连续工作多久？
       ↓
计算关节或车轮输出端的转矩、转速需求
       ↓
选择传动方式，换算到电机轴
       ↓
核对电机、减速机、驱动器和电源
       ↓
实际测试温升、运动和负载能力
```

我们用你熟悉的**机械臂关节**走一遍。

**① 先明确负载和动作要求**

假设要设计一个抬臂关节，先给出以下教学条件：

| 条件 | 假设值 |
|---|---:|
| 末端物体质量 | 1 kg |
| 关节到物体的距离 | 0.2 m |
| 连杆质量 | 0.5 kg |
| 连杆重心到关节的距离 | 0.1 m |
| 要达到的关节角速度 | 1 rad/s |
| 加速时的角加速度 | 2 rad/s² |

这些才是选型输入。

**只有“要抬起 1 kg”还不够。** 同样的物体，离关节越远，通常需要越大的转矩。

---

**② 先算“静止托住”需要多少转矩**

杆水平时，重力的力臂最大：

```text
关节 O───────────●───────────●
                连杆重心      物体
                  ↓            ↓
                0.5 kg        1 kg
       ← 0.1 m →
       ←────── 0.2 m ────────→
```

物体产生的重力转矩：

\[
\tau_{\mathrm{物体}}
=1\times9.81\times0.2
=1.962\ \mathrm{N\cdot m}
\]

连杆自身产生的重力转矩：

\[
\tau_{\mathrm{连杆}}
=0.5\times9.81\times0.1
=0.4905\ \mathrm{N\cdot m}
\]

合计：

\[
\boxed{\tau_{\mathrm{保持}}=2.4525\ \mathrm{N\cdot m}}
\]

也就是说，**还没开始加速，只是水平托住，就已经需要约 2.45 N·m。**

如果是多关节机械臂，还要计入这个关节后面的其他连杆、电机、夹爪及负载。

---

**③ 再算“加速抬起”需要增加多少转矩**

加速需要克服转动惯性：

\[
\tau_{\mathrm{加速}}=I\alpha
\]

这里：

- \(I\)：负载绕该关节轴的转动惯量。
- \(\alpha\)：角加速度。

**文档用 \(J\) 表示转动惯量，别把它与上一章的雅可比矩阵 \(J(q)\) 混淆。这里我用 \(I\) 区分。**

假设连杆是均匀细杆，长 0.2 m：

\[
I_{\mathrm{连杆}}=\frac13mL^2
=\frac13\times0.5\times0.2^2
\approx0.00667\ \mathrm{kg\cdot m^2}
\]

把末端物体视为质点：

\[
I_{\mathrm{物体}}=mr^2
=1\times0.2^2
=0.04\ \mathrm{kg\cdot m^2}
\]

因此：

\[
\tau_{\mathrm{加速}}
=(0.00667+0.04)\times2
\approx0.0933\ \mathrm{N\cdot m}
\]

如果再**假设**这一工况下摩擦阻力矩为 0.1 N·m，那么水平位置向上加速时，输出端需求约为：

\[
\tau_{\mathrm{需求}}
=2.4525+0.0933+0.1
\approx\boxed{2.65\ \mathrm{N\cdot m}}
\]

这仍是简化估算，没有计入电机和传动自身的惯性。

---

**④ 同时明确转速，不能只看转矩**

目标角速度为：

\[
\omega=1\ \mathrm{rad/s}
\]

转换成每分钟转数：

\[
n=\omega\frac{60}{2\pi}
\approx\boxed{9.55\ \mathrm{rpm}}
\]

所以现在的需求是：

> **在相关运动阶段，关节输出端需要提供约 2.65 N·m，并达到约 9.55 rpm。**

实际选型要看整条运动轨迹中的转矩与转速组合，不能总是假定最大转矩与最大转速同时出现。

---

**⑤ 如果使用减速机，把需求换算到电机轴**

假设减速比：

\[
i=20
\]

假设该运动工况下效率：

\[
\eta=0.8
\]

那么电机转速需要：

\[
n_{\mathrm{电机}}
=i\,n_{\mathrm{关节}}
=20\times9.55
\approx191\ \mathrm{rpm}
\]

仅考虑传递上述负载转矩，电机轴需要：

\[
\tau_{\mathrm{电机}}
\approx\frac{\tau_{\mathrm{关节}}}{i\eta}
=\frac{2.65}{20\times0.8}
\approx0.166\ \mathrm{N\cdot m}
\]

```text
电机轴                         减速机输出／关节轴
约 191 rpm ── 20:1 减速 ──→ 约 9.55 rpm
约 0.166 N·m ─────────────→ 约 2.65 N·m
```

这只是初步换算，后续还要计入电机转子惯性、实际效率等。减速机本身也必须承受输出转矩。

---

**⑥ 查电机资料时，最重要的是区分这三个量**

| 参数 | 怎样理解 |
|---|---|
| 连续转矩 | 在规定散热、温度等条件下，可以持续提供的转矩 |
| 峰值转矩 | 在规定时长和条件内，允许短时间提供的转矩 |
| 堵转转矩 | 转速为零时的特定工况转矩，不能直接当作长期工作能力 |

**“最大转矩 3 N·m”不代表能长期托住需要 2.5 N·m 的机械臂。** 必须看它说的是连续、峰值还是堵转转矩。

厂商选型资料会同时检查持续或等效负载、峰值需求，以及指定电压下能否达到所需转速。[maxon 选型资料](https://www.maxongroup.co.kr/medias/sys_master/8805405622302.pdf)

你文档里画的“空载转速—堵转转矩”直线，适合帮助理解能力变化，**但曲线下方不能全部叫作可长期工作的安全区域**。

---

**⑦ 最后确认“能不能精确控制、能不能装上、能不能供电”**

除了转矩和转速，还要核对：

| 要求 | 检查内容 |
|---|---|
| 准确到指定角度 | 编码器、位置控制能力、传动间隙 |
| 能接 AM970 | 通信接口、SDK 或协议、ARM64 适配 |
| 能持续运行 | 温升、散热、工作周期 |
| 能正常供电 | 电压、持续电流、峰值电流、驱动器能力 |
| 能装进机械结构 | 尺寸、重量、轴径、安装孔和轴承承载 |

你这类“关节到指定角度并保持”的任务，需要相应的位置控制与反馈能力；不能只根据电机能否旋转来判断。[maxon 控制器选型说明](https://support.maxongroup.com/hc/en-us/articles/360015382019-EPOS4-ESCON2-ESCON-What-controller-should-I-select)

**你现在先记住这个顺序：负载和动作要求 → 输出端转矩、转速 → 减速比换算 → 连续与峰值能力 → 控制接口与供电。**

如果机械臂已经买好了，通常先查现有电机和控制器参数，判断它能承担什么任务，而不是马上重新选电机。

## 5 代码解释问答原文

### 用户问题原文

解释和关联一下这个代码

### 回答原文

你指的是 **《05执行器原理与选型》最后的“电机选型计算器”代码**。它把我们刚讨论的选型流程写成了程序：

```text
小车有多重、轮子多大、要跑多快、加速多快、爬多陡
                         ↓
                  计算需要的推力
                         ↓
              换算成车轮转矩和转速
                         ↓
                与候选电机曲线比较
```

**先明确：这段代码只是计算和画图，不会连接 AM970，也不会让电机运动。**

---

**1. 输入参数就是“任务要求”**

```python
def motor_sizing_calculator(mass, radius, max_vel, max_acc, slope_deg):
```

五个参数分别是：

| 参数 | 含义 | 本例数值 |
|---|---|---:|
| `mass` | 小车总质量 | 10 kg |
| `radius` | 车轮半径 | 0.05 m |
| `max_vel` | 目标速度 | 1 m/s |
| `max_acc` | 用于计算的加速度 | 1 m/s² |
| `slope_deg` | 坡度角 | 10° |

调用代码：

```python
T_req, RPM_req = motor_sizing_calculator(
    mass=10,
    radius=0.05,
    max_vel=1.0,
    max_acc=1.0,
    slope_deg=10,
)
```

意思是：

> 假设一辆 10 kg 的小车，轮子直径 10 cm，要在 10° 坡上以 1 m/s² 加速，并检查 1 m/s 速度下的需求。

这里把速度和加速度要求组合为一个计算工况。实际轨迹中，最大速度与最大加速度不一定同时出现。

---

**2. 先计算车轮需要提供多大的推力**

```python
g = 9.81
mu = 0.05
```

- `g`：重力加速度。
- `mu`：代码假设的阻力系数。

这里用 `mu × 法向力` 近似运动阻力，可以把它理解为简化的滚动阻力模型。**它不是用来判断轮胎会不会打滑的附着系数。**

沿着上坡方向看：

```text
                  小车前进方向 →
车轮牵引力  →  [ 小车 ]
               ← 坡上的重力分量
               ← 运动阻力

牵引力还要有剩余，才能使小车加速。
```

对应牛顿第二定律：

\[
F_{\mathrm{牵引}}-F_{\mathrm{坡度}}-F_{\mathrm{阻力}}=ma
\]

移项：

\[
F_{\mathrm{牵引}}=ma+F_{\mathrm{坡度}}+F_{\mathrm{阻力}}
\]

代码就是分三项计算。

**第一项：用于加速的力**

```python
F_acc = mass * max_acc
```

对应：

\[
F_{\mathrm{acc}}=ma=10\times1=\boxed{10\ \mathrm N}
\]

它与刚才机械臂例子中的 \(I\alpha\) 对应：

| 直线运动 | 转动 |
|---|---|
| \(F=ma\) | \(\tau=I\alpha\) |
| 质量决定加速难度 | 转动惯量决定加速难度 |

**第二项：抵抗沿坡向下的重力分量**

```python
F_gravity = mass * g * np.sin(np.radians(slope_deg))
```

对应：

\[
F_{\mathrm{gravity}}=mg\sin\beta
\]

其中 \(\beta\) 是坡度角。代入：

\[
F_{\mathrm{gravity}}
=10\times9.81\times\sin10^\circ
\approx\boxed{17.03\ \mathrm N}
\]

`np.radians()` 先把度转换为弧度，才能交给 `np.sin()`。

这里**不是拿全部重力 \(mg\) 当作前进阻力**，而是取沿坡方向的分量。

**第三项：运动阻力**

```python
F_friction = mass * g * np.cos(np.radians(slope_deg)) * mu
```

简化模型中的法向力：

\[
N=mg\cos\beta
\]

因此：

\[
F_{\mathrm{friction}}=\mu mg\cos\beta
\]

代入：

\[
F_{\mathrm{friction}}
=0.05\times10\times9.81\times\cos10^\circ
\approx\boxed{4.83\ \mathrm N}
\]

**三项相加：**

```python
Total_Force = F_acc + F_gravity + F_friction
```

\[
F_{\mathrm{总需求}}
=10+17.03+4.83
\approx\boxed{31.87\ \mathrm N}
\]

这就是这个简化工况下，全车驱动轮需要合计提供的牵引力。

---

**3. 把推力转换成车轮转矩**

```python
Required_Torque = Total_Force * radius
```

对应：

\[
\tau_{\mathrm{轮侧}}=Fr
\]

代入：

\[
\tau_{\mathrm{轮侧}}
=31.87\times0.05
\approx\boxed{1.59\ \mathrm{N\cdot m}}
\]

可以这样理解：

```text
车轮输出转矩 τ
       ↓ 轮子与地面接触
形成牵引力 F

τ = F × 车轮半径
```

**这一行与机械臂的“力 × 力臂”是同一类转矩关系。**

但原代码的注释写成“转换为电机轴参数”，不够准确：**目前算的是轮侧需求，还没有考虑减速机。**

如果两个相同驱动轮平均分担牵引力，则每个轮子的需求约为：

\[
\tau_{\mathrm{单轮}}=\frac{1.59}{2}
\approx0.80\ \mathrm{N\cdot m}
\]

如果每个轮子还带减速机，则进一步计算：

\[
\tau_{\mathrm{电机}}
\approx\frac{\tau_{\mathrm{单轮}}}{i\eta}
\]

这里的平均分担是假设，实际还取决于载荷分配和驱动方式。

---

**4. 把小车速度转换成车轮转速**

```python
omega = max_vel / radius
```

无打滑滚动时：

\[
v=\omega r
\]

所以：

\[
\omega=\frac vr=\frac1{0.05}
=\boxed{20\ \mathrm{rad/s}}
\]

然后：

```python
Required_RPM = omega * 60 / (2 * np.pi)
```

因为一圈等于 \(2\pi\) rad，一分钟有 60 秒：

\[
n=\frac{\omega}{2\pi}\times60
\]

\[
n=\frac{20}{2\pi}\times60
\approx\boxed{190.99\ \mathrm{rpm}}
\]

这还是**车轮转速**。如果有减速比 \(i\)，电机轴需要：

\[
n_{\mathrm{电机}}=i\,n_{\mathrm{车轮}}
\]

所以该函数输出的是：

```text
轮侧总转矩需求：约 1.59 N·m
车轮转速需求：约 191 rpm
```

**5. 后半段代码是在假设一台候选电机**

```python
motor_no_load_rpm = 300
motor_stall_torque = 3.0
```

这两个数是人为设定的，并没有从真实电机读取：

- 空载转速：300 rpm。
- 堵转转矩：3 N·m。

程序用一条直线连接两个点：

```text
转矩 N·m
  3 ●
    │ ╲
    │   ╲
    │     ╲
    │       ╲
  0 └─────────●────→ 转速 rpm
    0        300
```

含义是：在这个简化模型和给定条件下，转速越高，可提供的转矩越小。

生成这条线的代码：

```python
rpm_range = np.linspace(0, motor_no_load_rpm, 100)
```

在 0～300 rpm 之间取 100 个点。

```python
slope = -motor_stall_torque / motor_no_load_rpm
```

计算斜率：

\[
k=-\frac3{300}=-0.01
\]

```python
torque_curve = slope * rpm_range + motor_stall_torque
```

得到：

\[
\boxed{\tau(n)=3-0.01n}
\]

这只是给定条件下的直流电机近似特性线，不能代表所有电机和控制模式。

**6. 红点与蓝线比较，具体比什么？**

画蓝线：

```python
plt.plot(rpm_range, torque_curve, ...)
```

画需求红点：

```python
plt.plot(RPM_req, T_req, 'ro', ...)
```

红点位置是：

\[
(n,\tau)\approx(191,\ 1.59)
\]

在 191 rpm 时，候选曲线给出的转矩约为：

\[
\tau_{\mathrm{候选}}
=3-0.01\times191
=\boxed{1.09\ \mathrm{N\cdot m}}
\]

而需求是：

\[
\tau_{\mathrm{需求}}\approx1.59\ \mathrm{N\cdot m}
\]

因此：

\[
1.59>1.09
\]

**按照代码直接比较的简化模型，红点在蓝线上方，候选曲线不能满足这个需求点。**

但要记住：代码拿的是全车轮侧总需求。只有候选曲线也对应同一个输出轴和驱动分配条件，这个比较才成立。不能拿两轮合计需求，直接判定每一台电机都不够。

其余画图代码主要负责显示：

| 代码 | 作用 |
|---|---|
| `fill_between(...)` | 给曲线下方涂色，不会增加任何物理验证 |
| `axvline(...)` | 标出需求转速 |
| `axhline(...)` | 标出需求转矩 |
| `xlabel/ylabel` | 标注坐标单位 |
| `legend()` | 显示图例 |
| `show()` | 弹出图形窗口 |
