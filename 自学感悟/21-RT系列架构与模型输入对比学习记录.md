## 1. 这一篇主要学习什么？

这一篇重点理解三个问题：机器人怎样用 Transformer 学动作，怎样利用视觉语言模型的知识，以及不同机器人怎样共享训练经验。

| 系列 | 主要研究的问题 | 与前面学习的关联 |
|---|---|---|
| RT-1 | 怎样从画面和指令预测机器人动作？ | 示范数据、动作离散化、监督训练 |
| RT-2 | 怎样让预训练视觉语言模型学会输出动作？ | OpenVLA 的“视觉＋语言→动作 token”路线 |
| RT-X | 不同机器人采集的示范能否一起训练，互相帮助？ | 多来源机器人数据与动作适配 |

RT-X 包含基于 RT-1、RT-2 的模型，不是简单换了一种结构的“RT-3”。它的重点是跨机器人数据训练。

```text
机器人示范：图片＋指令＋动作
              │
              ↓
RT-1：训练模型，根据观察和指令预测动作
              │
              ↓
RT-2：进一步利用已有视觉语言模型的知识
              │
              ↓
RT-X：进一步研究不同机器人的经验能否共享
```

这张图表示学习上的递进关系，不表示每个模型必须依次加载上一个模型的权重。

参考：[RT-X 官方介绍](https://robotics-transformer-x.github.io/)。

## 2. RT-1 究竟在做什么？

对应教程[第 2 节](E:/cpp_project/robot_ai_learn/06-策略抓取或抓取VLA/大模型控制、VLA、VLM/03RT系列论文解读与代码分析/01RT系列论文解读与代码分析.md:15)。

沿用前面的例子：桌上有杯子，指令是“拿起杯子”。

```text
最近几帧相机画面          语言指令：“拿起杯子”
        │                          │
        └────────────┬─────────────┘
                     ↓
                   RT-1
                     ↓
              预测当前动作 token
                     ↓
              解码成机器人动作
                     ↓
             控制系统执行这个动作
                     ↓
              相机获得新的画面
                     │
                     └────→ 再次输入模型
```

需要留意：

- RT-1 使用一小段图像序列，包含近期的视觉信息。
- 它反复根据新观察输出动作，形成闭环控制。

单次推理可以理解成：

> 根据我最近看到的情况，为了完成这个指令，现在应该怎么动？

这与前面学过的 OpenVLA 推理闭环能够对应。模型输出的动作仍需要交给具体机器人的控制系统执行，不能把动作 token 直接当作电机力矩。

参考：[RT-1 官方介绍](https://robotics-transformer1.github.io/)。

## 3. EfficientNet、FiLM、Token Learner 和 Transformer 各自干什么？

对应教程[2.1 模型架构](E:/cpp_project/robot_ai_learn/06-策略抓取或抓取VLA/大模型控制、VLA、VLM/03RT系列论文解读与代码分析/01RT系列论文解读与代码分析.md:19)。

```text
相机图片                         语言指令
   │                                │
   ↓                                ↓
EfficientNet                    语言编码
提取视觉特征                        │
   │                                │
   └────────── FiLM 调节 ←───────────┘
                    │
                    ↓
           与任务有关的视觉特征
                    │
                    ↓
              Token Learner
           压缩成较少的视觉 token
                    │
                    ↓
               Transformer
                    │
                    ↓
                动作 token
```

这是按职责展开的示意图。FiLM 调节融入视觉编码过程，并非必须等完整视觉编码结束后再单独运行一次。

### 3.1 EfficientNet：把图片变成视觉特征

输入是像素，输出是数值特征表示：

```text
图片中的颜色、边缘、形状、空间布局
                  ↓
             数值特征表示
```

RT-1 使用的 EfficientNet 是卷积神经网络。前面看到的 OpenVLA 使用视觉 Transformer。视觉编码器可以采用不同结构，并不是所有相关机器人模型都必须使用同一种视觉网络。

### 3.2 FiLM：让指令参与视觉特征处理

假设画面里同时有杯子和苹果：

```text
同一张图片
    │
    ├── 指令：“拿起杯子”
    │       ↓
    │   视觉特征的处理受到“杯子任务”的调节
    │
    └── 指令：“拿起苹果”
            ↓
        视觉特征的处理受到“苹果任务”的调节
```

FiLM 可以理解成：根据语言，对视觉特征的不同通道进行缩放、偏移。

它不是先人工画一个框把其他物体删掉，而是在模型内部调节特征。语言因此能够影响模型怎样利用画面信息。

### 3.3 Token Learner：减少后面需要处理的视觉信息数量

前面的视觉特征比较多，全部交给 Transformer 会增加计算量。Token Learner 学习将它们汇总成较少的视觉 token：

```text
较多的视觉特征
       ↓
学习怎样提取、汇总信息
       ↓
较少的视觉 token
```

这里的两种 token 必须区分：

| 名称 | 表示什么 |
|---|---|
| 视觉 token | 图片中提取出的特征表示 |
| 动作 token | 动作数值离散化后的类别编码 |

**它们都叫 token，但内容和用途不同。视觉 token 不等于动作类别，也不一定是整数编号。**

### 3.4 Transformer：根据这些信息预测动作

模型利用受语言调节的视觉信息，预测动作的离散类别：

```text
动作类别预测
      ↓
动作 token
      ↓
解码后的动作数值
      ↓
机器人控制接口
```

结构依据：[RT-1 官方架构说明](https://robotics-transformer1.github.io/#approach)。

## 4. RT-1 训练时的答案从哪里来？

答案来自示范数据：

```text
示范中的近期图片＋指令
              ↓
            RT-1
              ↓
         预测动作类别
              │
              │ 对照
              ↓
     示范动作离散化后的目标类别
              ↓
           计算损失
              ↓
           更新参数
```

前面已经理解的关系仍然成立：

> 当前观察和指令是条件，示范动作是学习目标。

RT-1 的主要训练方式是基于示范的模仿学习。推理时机器人反复与环境交互，不代表训练就一定是 PPO 那样的强化学习。需要区分“执行动作后获取新观察”和“根据奖励更新策略参数”。

参考：[RT-1 官方介绍](https://robotics-transformer1.github.io/)。

## 5. 读原教程时需要注意的边界

### 5.1 OpenVLA 不能简单等同于 RT-2 的相同实现

教程把 OpenVLA 称作“RT-2 的开源复现版”，容易让人误以为两者代码、结构和训练设置完全相同。

更准确的理解是：

> OpenVLA 与 RT-2 属于相关的 VLA 技术路线，可以对照学习，但不能当成同一个模型。

RT-2 利用预训练视觉语言模型，并联合机器人示范和视觉语言任务进行微调。OpenVLA 的具体结构应以前面检查过的本地实现为准。

参考：[RT-2 官方介绍](https://robotics-transformer2.github.io/)、[OpenVLA 官方介绍](https://openvla.github.io/)。

### 5.2 教程的动作分词代码要按教学示例来读

位置：[2.3 动作分词器](E:/cpp_project/robot_ai_learn/06-策略抓取或抓取VLA/大模型控制、VLA、VLM/03RT系列论文解读与代码分析/01RT系列论文解读与代码分析.md:39)。

该示例编码时使用：

```python
action_tokens = np.floor(action_norm * (self.vocab_size - 1)).astype(np.int32)
```

解码时使用：

```python
action_norm = (action_tokens + 0.5) / self.vocab_size
```

两边的区间划分约定没有完全对应。因此不能直接照着当成严格配套的分词器，也不能把这个类名当成它就是官方源码的证明。

后续学习动作分词时，再具体展开区间、边界、类别编号和解码代表值之间的关系。本次没有修改原教程代码。

## 6. 用户提问：SmolVLA 是图片＋指令＋状态，OpenVLA 是图片＋指令，对吧？

用户原问题：

> 我记得smolVLA是用图片+指令+机器状态，openVLA是图片+指令对吧

**对，就前面学习的 SmolVLA 和原版 OpenVLA 而言，这个理解正确。**

| 模型 | 推理时的主要输入 | 输出 |
|---|---|---|
| SmolVLA | 图片＋语言指令＋机器人状态 | 一段连续动作，即动作块 |
| 原版 OpenVLA | 图片＋语言指令 | 动作 token，解码成当前一步的动作 |

这里限定的是已学习的模型版本和调用路径，不能直接推广为所有名称相近的改版或后续模型。

### 6.1 SmolVLA 三种输入分别提供什么信息？

```text
图片：外部环境是什么样？
例如：杯子在哪里，夹爪与杯子是什么关系。

指令：要完成什么任务？
例如：拿起杯子。

机器人状态：机器人自身现在是什么状态？
例如：当前关节角度、夹爪开合位置。
具体包含哪些量，取决于数据集和机器人配置。
```

```text
图片 ──────→ 看环境 ────────┐
指令 ──────→ 明确任务 ──────┼──→ SmolVLA → 动作块
机器人状态 → 提供自身状态 ──┘
```

这张图说明信息来源，不表示三个输入都是以相同方式进入同一个编码器。状态作为条件输入，与训练时作为监督目标的示范动作也不是同一个概念。

### 6.2 原版 OpenVLA 不单独输入状态，是否完全不知道机器人位置？

原版 OpenVLA 根据图片和指令预测动作，没有单独接收这一路机器人状态。

图片里也可能看得到机械臂、夹爪的位置，但这种视觉信息不等于直接输入精确的关节角数值。

```text
从图片看见夹爪的位置关系
              ≠
直接读取每个关节的角度数值
```

同时，“策略模型不接收关节状态”不意味着底层控制器不需要状态反馈。模型输入与机器人控制系统使用的信息，需要分开理解。

### 6.3 observation 里面有 state，为什么仍然说 OpenVLA 不用状态？

因为字典存了某个字段，不代表模型实际接收了它。

```text
环境返回：图片＋机器人状态等
                  ↓
推理代码从中选择模型需要的字段
                  ↓
原版 OpenVLA 实际接收：图片＋指令
```

前面 LIBERO 推理代码构造的 observation 字典即便包含 `state`，也不能据此判断 OpenVLA 使用了状态。必须继续追踪实际传入模型的参数。

本地代码入口：[openvla_utils.py 中的 get_vla_action](E:/cpp_project/openvla/experiments/robot/openvla_utils.py:127)。

### 6.4 再把 RT-1 加进来对照

```text
RT-1：          近期多帧图片＋指令 → 动作
原版 OpenVLA：  当前图片＋指令     → 动作
SmolVLA：       图片＋指令＋状态   → 动作块
```

这张图比较的是本次学习配置下的主要策略输入输出；SmolVLA 的图像数量、相机视角和状态内容还要看具体配置。动作块中的动作可以按执行策略逐步取出使用，不代表瞬间执行完一整段。

**VLA 这个名称并不规定所有模型的输入完全相同，具体要看模型设计和实际调用代码。**
