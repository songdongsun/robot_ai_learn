# PID 控制与机器人动力学学习记录

学习日期：2026-10-27。

对应资料：`02-机器人基础和控制、手眼协调/补充02PID_Control.md`。

这次讨论的重点是：PID 的三个分量分别做什么，PID 输出是否一定是力矩，以及 PID、动力学模型、电机和仿真器在实际系统中怎样配合。

## 1 从机器人动力学进入控制问题

机器人动力学常写为：

```text
M(q)q̈ + C(q,q̇)q̇ + g(q) = τ
```

其中 q 是关节位置，q̇ 是关节速度，q̈ 是关节加速度，M 是惯性矩阵，C(q,q̇)q̇ 是科里奥利及离心项，g 是重力项，τ 是关节驱动力矩。这里暂时省略摩擦和外部接触力等项。

动力学描述力矩与运动之间的关系。控制器需要解决的是：为了达到目标运动，现在应该给出什么控制指令？

在直接力矩控制中，可以使用 PID 根据关节角度误差计算目标力矩，再让电机执行。

```text
目标角度 → 与实际角度比较 → PID → 目标力矩 → 电机和机械臂运动
                   ↑                                  │
                   └──────── 传感器反馈实际角度 ────────┘
```

不断测量、比较和调整，形成闭环控制。

## 2 PID 公式与三个分量

定义误差：

```text
e(t) = 目标值 − 实际值
```

连续时间 PID 为：

```text
u(t) = Kp·e(t) + Ki·∫e(s)ds + Kd·de(t)/dt
```

积分从控制开始时刻累积到当前时刻。u 是控制输出，具体单位由控制接口决定。

| 分量 | 依据 | 作用 |
| --- | --- | --- |
| P 比例 | 当前误差 | 误差越大，产生越大的纠正输出 |
| I 积分 | 历史误差累积 | 补偿持续偏差，在适当条件下消除稳态误差 |
| D 微分 | 误差变化速度 | 根据变化趋势调整输出，常用于增加阻尼、抑制超调 |

### P 当前差多少就按比例纠正

假设目标是 90°，实际为 60°，误差是 30°。比例项为 u_P = Kp·e。

随着关节接近目标，误差变小，P 输出也变小。角度用度只是便于理解；机器人计算通常使用弧度，增益单位也必须相应匹配。

如果关节需要持续输出力矩来抵抗重力，仅用 P 时可能停在 88°：剩下的 2° 误差产生的力矩恰好抵消负载，关节便不再继续靠近 90°。这种持续存在的目标偏差叫稳态误差。

这不是说所有系统的 P 控制都会留下稳态误差；是否存在取决于系统动力学、输入和负载。

### I 把持续存在的误差积累起来

积分项为 u_I = Ki·∫e(t)dt。如果误差一直为正，积分继续增加，推动系统进一步接近目标。

一个关键点：误差变成零，不表示积分值自动变成零，而是积分不再因这一时刻的零误差而增加。先前积累的输出可以继续抵抗重力或其他恒定负载。

积分过多可能引起超调。尤其当执行器已经达到最大输出，误差仍持续累积时，会出现积分饱和问题；控制器需要结合输出限制采用积分限幅或其他抗积分饱和措施。

### D 根据误差变化趋势调整

假设目标固定为 90°：

```text
实际角度：60° → 75° → 85°
误差：    30° → 15° →  5°
```

误差正在减小，de/dt 为负，正的 Kd 会产生负的 D 输出，抵消部分正向驱动，类似提前刹车。

固定目标时：

```text
e = q_d − q
ė = −q̇
u_D = −Kd·q̇
```

因此 D 项表现得像阻尼，反抗过快的运动。目标随时间变化时，ė = q̇_d − q̇，不能直接忽略目标速度。

文档把 D 描述为“预测”，更准确地说，它使用误差的变化趋势，并没有显式预测未来轨迹。微分也容易放大测量噪声，因此实际实现常需要滤波。

## 3 Python 示例怎样对应公式

下面是文档中核心计算的整理版本，用来解释每次更新做什么：

```python
# 目标值减去当前测量值，得到本次误差。
error = self.setpoint - measured_value

# 用“本次误差 × 时间间隔”近似这一小段时间的积分。
self.integral += error * self.sample_time

# 用相邻两次误差的差值除以时间间隔，近似误差导数。
derivative = (error - self.prev_error) / self.sample_time

# 三个分量相加，得到当前控制输出。
output = (
    self.Kp * error
    + self.Ki * self.integral
    + self.Kd * derivative
)

# 保存本次误差，供下次计算差分。
self.prev_error = error
```

sample_time 必须与实际调用间隔相匹配。每次调用 update() 只计算一个时刻的输出；完整闭环还需要周期性读取传感器、调用 update()、发送输出。

文档示例只调用一次并打印结果，没有连接真实电机或仿真器，所以不能仅凭这个示例断定 output 的物理单位。

例子中 setpoint=100、measured_value=90、sample_time=0.01，初始 prev_error=0、integral=0：

```text
error = 10
integral = 10 × 0.01 = 0.1
derivative = (10 − 0) / 0.01 = 1000

Kp=1、Ki=0.1、Kd=0.01 时：
output = 1×10 + 0.1×0.1 + 0.01×1000 = 20.01
```

第一次的微分结果受到 prev_error=0 这个初始化约定影响，不能据此认为实际测量已经出现了这样的变化速度。目标突变也可能使对误差求微分的控制器产生较大的瞬时输出。

“位置式 PID”表示直接计算完整输出 u，不意味着只能控制位置。增量式 PID 则计算输出变化量 Δu，再累加到原输出上。

## 4 PID 与力矩有什么关系

PID 是计算控制指令的方法，力矩可以是它的输出。它们不是两个彼此独立、并行工作的东西。

直接力矩控制时：

```text
τ_PID = Kp·e + Ki·∫e dt + Kd·ė
M(q)q̈ + C(q,q̇)q̇ + g(q) = τ_PID
```

PID 决定施加多少目标力矩，机器人动力学决定这些力矩将产生怎样的运动。这里为了说明关系，暂时假设目标力矩能够被执行器准确实现。

但是 PID 不一定直接输出力矩：

| 接收输出的接口 | PID 输出的含义 |
| --- | --- |
| 关节力矩接口 | 目标力矩 |
| 电流接口 | 目标电流，电机再产生力矩 |
| 速度接口 | 目标速度，由底层控制器继续驱动执行器 |

阅读代码时应追踪 output 最终传给谁，不能仅根据变量叫 output 或 control_input 判断它是力矩。

## 5 PID 参数与动力学参数有关联吗

有关联，但 PID 增益不是质量或惯量本身，也不自动等于某个动力学参数。

用一个忽略重力、摩擦的单关节说明：

```text
Jq̈ = τ
```

J 是转动惯量。若只用 P 控制：

```text
τ = Kp(q_d − q)
q̈ = (Kp/J)(q_d − q)
```

因此：

- 同样误差下，Kp 越大，输出力矩越大。
- 同样力矩下，J 越大，角加速度越小。
- 负载、姿态等改变有效惯量和其他动力学因素后，相同增益会产生不同的响应。

数值例子：角度误差 e=0.1 rad，Kp=20 N·m/rad，则比例项输出为 2 N·m。

如果控制输入确实是力矩，误差是角度，增益常见单位为：

```text
Kp：N·m/rad
Ki：N·m/(rad·s)
Kd：N·m·s/rad
```

换成速度误差或其他输出接口后，增益的单位也会改变。

## 6 实际机器人里是否先算力矩再交给动力学

对于直接力矩 PID，先算目标力矩的理解是对的。但真实机器人和仿真中的“动力学”承担方式不同。

### 真实机器人

```text
目标角度与实际角度
        ↓
PID 计算目标力矩 τ_cmd
        ↓
驱动器控制电流，使电机产生力矩
        ↓
真实机械臂按物理规律运动
        ↓
编码器测得新的角度，反馈给 PID
```

真实机械臂不需要先运行一个动力学计算程序才会运动。就像用手推小车，小车自然遵循物理规律。

驱动器把目标力矩转换成电机控制时，需要考虑电机力矩常数、传动比以及系统限制。目标力矩与实际力矩可能因为饱和、摩擦和控制误差而不同。

### MuJoCo 等仿真器

```text
控制器给出驱动力矩
        ↓
MuJoCo 根据惯量、重力、接触等计算状态变化
        ↓
得到新的关节角度和速度
        ↓
反馈给控制器
```

仿真中没有真实机械臂，软件负责计算被控对象的物理响应。这才是把力矩送给动力学计算的情形。

## 7 力矩一定全部由 PID 算出来吗

不一定。动力学模型也可以参与计算驱动力矩。

### 方式一 由 PID 提供全部目标力矩

```text
τ_cmd = τ_PID
```

控制器根据实际误差不断修正，不要求显式使用完整的机器人动力学模型。

### 方式二 重力补偿加 PID

```text
τ_cmd = ĝ(q) + τ_PID
```

ĝ(q) 是模型估算的重力补偿力矩。模型先估计托住机械臂需要多少力矩，PID 根据实际误差补充修正。

例如，模型估计保持当前姿态需要 4 N·m；机械臂还略低于目标，PID 计算出额外 0.5 N·m，则总目标力矩为 4.5 N·m。

```text
当前关节姿态 → 动力学模型 → 重力补偿力矩 ──┐
                                          ├→ 相加 → 电机
目标与实际误差 → PID → 修正力矩 ───────────┘
```

两部分在这里可以作为并行计算的分支，但最终共同组成同一个力矩指令。模型补偿和反馈控制分别承担预计负载与实际偏差修正。

### 方式三 运动前馈加反馈

对于目标轨迹，模型还可以根据目标位置、速度和加速度，估算惯性、运动耦合与重力所需的力矩，再加反馈修正。例如一种轨迹前馈形式：

```text
τ_ff = M̂(q_d)q̈_d + Ĉ(q_d,q̇_d)q̇_d + ĝ(q_d)
τ_cmd = τ_ff + τ_feedback
```

帽子表示模型估计值。实际有不同的模型控制结构，不能把所有结构都当成同一个 PID 公式。反馈仍用来修正模型误差、扰动和跟踪偏差。

## 8 对应之前的 MuJoCo examples

示例 XML 中有：

```xml
<position joint="shoulder_pan" kp="120"/>
```

这是位置执行器，接收目标关节位置。因此：

```python
data.ctrl[0] = 0.5
```

对这个旋转关节表示目标角度 0.5 rad，而不是 0.5 N·m。

在示例的简单单位关节传动下，位置执行器按比例关系产生驱动力矩：

```text
τ ≈ kp(q_target − q)
```

完整路径是：

```text
Python 通过 IK 和轨迹规划生成目标关节角
        ↓
写入 data.ctrl
        ↓
位置执行器根据位置误差产生力矩
        ↓
MuJoCo 动力学计算实际运动
```

这个位置执行器配置不是完整 PID：XML 给出的是位置比例增益，关节上另外设置了 damping。关节阻尼会影响运动，但不能据此声称程序实现了完整的 P、I、D 三项控制。

如果使用可直接施加关节力矩的执行器接口，就可以在 Python 中自行计算 PID 或模型补偿力矩，再发送给执行器；仍需确认传动、增益和限制如何把 ctrl 映射成实际关节力矩。

## 9 P I D 如何配合与相互牵制

三个分量不直接修改彼此，而是根据同一个误差及其历史、变化率，各自计算输出，再相加：

```text
u_P = Kp·e
u_I = Ki·∫e dt
u_D = Kd·ė
u = u_P + u_I + u_D
```

同方向的输出会加强，反方向的输出会抵消。合成输出使机器人运动，运动又改变误差，进而影响三个分量，这才构成它们在闭环中的联系。

下面以关节从 0° 转到固定目标 90° 为例，假设 Kp、Ki、Kd 为正、初始积分为零，并采用直接力矩控制。角度使用度仅用于说明；计算时通常用弧度。先不讨论目标突变瞬间的微分冲击，也暂时忽略输出饱和。

### 刚开始 P 推动运动 I 开始累积

实际角度低于目标，e = 90° − q 为正，而且较大，所以 P 提供较大的正向力矩。

只要正误差持续存在，积分就逐渐增加。机械臂开始向目标运动后，误差逐渐减小，因此 D 输出为负，抑制正向运动过快。如果目标已经固定且关节尚未运动，理想的 D 项为零。

### 接近目标 P 减弱 D 制动 I 可能仍在推动

假设关节到了 85°，但仍有较大的正向速度：

- P：误差只剩 5°，正向输出变小。
- I：之前积累的误差还在，可能继续提供较大的正向输出。
- D：误差快速下降，提供负向输出，帮助制动。

例如某一时刻三个力矩分量分别是：

```text
P = +1 N·m
I = +3 N·m
D = −2 N·m
合成力矩 u = 1 + 3 − 2 = +2 N·m
```

这些数值仅用于说明相加关系。D 抵消了部分正向输出，合成力矩仍为正。实际是在加速还是减速，还需要结合重力、阻力等动力学因素判断。

### 到达目标 P 为零不代表已经停下

关节经过 90° 时，位置误差为零，因此 P 为零。但关节可能仍有速度，I 也可能保留历史累积：

```text
e = 0 → P = 0
历史积分不一定为零 → I 不一定为零
关节仍在运动 → D 不一定为零
```

因此“位置到达目标”和“速度降到零”是两件事。机器人有惯性，即使某个时刻合成控制输出为零，也不能据此判断它会立即停下。

### 超过目标 P 往回拉 I 逐渐消退

假设实际角度为 95°，误差变为 −5°。此时 P 输出为负，要求关节返回目标。负误差开始抵消之前积累的正积分，但 I 不会瞬间变负，可能暂时还在正向推动。

如果关节仍然朝正方向运动，误差继续减小，D 为负，帮助制动；等关节开始返回，误差逐渐增加，D 转为正，抑制返回过快。

固定目标时 ė = −q̇，因此 u_D = −Kd·q̇。D 的符号跟随速度变化：它像阻尼，反抗运动，而不是永远输出负数。

### 不同阶段的分量方向

| 阶段 | P | I | D，目标固定时 |
| --- | --- | --- | --- |
| 低于目标并向目标运动 | 正，推动靠近 | 从零开始通常逐渐增加 | 负，抑制正向速度 |
| 接近目标但仍高速运动 | 正，但变小 | 可能仍较大 | 负，帮助制动 |
| 超过目标且继续向前 | 负，要求返回 | 可能仍为正，逐渐消退 | 负，继续制动 |
| 从超调位置往回运动 | 负，推动返回 | 取决于历史累积 | 正，抑制返回过快 |
| 停在目标上 | 零 | 可以保留负载补偿 | 零 |

最后一行的 I 不必为零：如果机械臂需要持续力矩抵抗重力，I 可以保留这部分输出。如果另有准确的重力补偿，则不一定需要积分承担这一负载。

### 参数之间如何取舍

Kp 太大可能让推动过于猛烈，造成超调或振荡。适当的 D 可以增加阻尼，但效果还取决于惯量、采样周期、延迟和执行器能力，不能把“增大 Kp 就同比增大 Kd”当作通用规则。

Ki 太大会让积分积累过快，接近目标后仍持续推动，容易造成超调或慢速往复摆动。如果执行器已经达到最大输出，积分仍不断累积，还会导致积分饱和。仅增加 D 不能代替抗积分饱和处理。

Kd 太大会放大测量噪声，使控制输出抖动；在一些系统中，也会因阻尼过大而使响应变慢。因此 D 通常需要结合测量质量和滤波使用。

对于学习单关节位置控制，可以先在仿真中看 P 如何将关节拉向目标，再加入 D 观察阻尼效果，最后根据持续偏差的需要加入 I。这是帮助理解的一种顺序，不是所有控制对象都适用的固定整定规则。

观察时最好同时记录目标角度、实际角度、速度、P/I/D 各自输出、最终输出和饱和状态。只看最终角度曲线，很难分辨是积分仍在推动，还是阻尼不足或执行器已饱和。

## 10 本次讨论的关键区别

| 概念 | 负责什么 |
| --- | --- |
| 运动学 | 关节状态与末端位姿之间的关系 |
| 动力学 | 力矩与机器人运动变化之间的关系 |
| PID | 根据误差计算当前控制指令 |
| 电机驱动器 | 把指令转成电机实际驱动 |
| 传感器 | 提供实际运动状态，形成反馈 |
| MuJoCo | 在仿真中计算物理对象的响应 |

判断某段程序时，依次追踪：目标是什么 → 测量什么 → 误差是什么 → 输出单位是什么 → 哪个执行器接收输出 → 新状态如何反馈。

后续学习可以先在单关节仿真中分别观察 P、PI、PD、PID 的响应，再讨论采样周期、限幅、积分饱和和微分滤波。文档中的 C 示例需要结合其数据结构与调用方式核查，不能直接把示例当作完整、已验证的电机控制实现。
