# 手眼标定详解

学习日期：2026-10-26。

对应资料：`02-机器人基础和控制、手眼协调/补充01手眼协调.md`，重点是 6.1.2 数学模型与 6.1.3 求解 AH = HB。

手眼标定要解决的问题是：相机测得的位置和姿态，如何转换到机器人使用的坐标系中。理解这篇内容的顺序是：明确坐标系与转换方向 → 找到不变的刚性连接关系 → 建立 AH = HB → 求旋转 → 求平移。

## 1 坐标系和符号的设计依据

四个字母分别表示：

| 字母 | 坐标系 |
| --- | --- |
| b | base，机器人基座 |
| e | end-effector，机械臂末端 |
| c | camera，相机 |
| t | target，标定板 |

文档使用 T 的上标表示目标坐标系，下标表示来源坐标系。例如 T^b_c 表示“相机坐标 → 基座坐标”。上标不是幂次，下标不是数组下标。

```text
p_b = T^b_c p_c

同一个点在相机中的坐标 p_c
          ↓ T^b_c
同一个点在基座中的坐标 p_b
```

这里的点使用齐次坐标 [x, y, z, 1]ᵀ。矩阵是：

```text
T = [ R  t ]
    [ 0  1 ]
```

R 是 3×3 旋转矩阵；t 是三维平移向量。t 表示来源坐标系原点在目标坐标系中的坐标。R 的三列分别是来源坐标系的 X、Y、Z 轴在目标坐标系中的方向。

T^b_c 既可以读成“把相机坐标转换为基座坐标”，也可以读成“相机在基座坐标系下的位姿”。它们是同一矩阵的两种解释。

### 为什么上下标会反过来

因为要沿相反方向转换：

```text
T^b_e：末端 → 基座
T^e_b：基座 → 末端

T^e_b = (T^b_e)⁻¹
```

假设坐标轴方向相同，末端原点位于基座右侧 1 米，那么：

```text
x_b = x_e + 1
x_e = x_b - 1
```

对于包含旋转的完整变换，取逆公式是：

```text
T⁻¹ = [ Rᵀ  −Rᵀt ]
      [  0     1   ]
```

不能只把平移改成负号，因为反向表达平移时还需要改变其坐标系。

### 为什么矩阵从右往左读

```text
T^b_e T^e_c p_c
```

先对 p_c 应用右边的 T^e_c，得到末端坐标，再应用 T^b_e，得到基座坐标。因此：

```text
相机 → 末端 → 基座
T^b_e T^e_c = T^b_c
```

中间坐标系必须接得上；矩阵乘法一般不能交换顺序。e₁、e₂ 表示同一个末端在两次拍照时的坐标系，不是两个机械臂末端。

## 2 Eye in Hand 的推导

相机固定在末端，标定板固定在桌面。机器人运动时：

- 相机与末端的安装关系 H = T^e_c 不变，是待求量。
- 标定板相对于基座的位姿 T^b_t 不变，但可以不知道具体数值。
- 机器人提供每次末端相对于基座的位姿。
- 标定板图像结合相机参数提供每次标定板相对于相机的位姿。

每次拍照都沿同一条转换链计算：

```text
标定板 → 相机 → 末端 → 基座
T^b_t = T^b_e H T^c_t
```

因为板和基座没动，两次结果相等。令 G_i = T^b_ei，C_i = T^ci_t，则：

```text
G₁ H C₁ = G₂ H C₂
```

两边左乘 G₂⁻¹，消去右边的 G₂：

```text
G₂⁻¹ G₁ H C₁ = H C₂
```

两边右乘 C₁⁻¹，消去左边最后的 C₁：

```text
(G₂⁻¹ G₁) H = H (C₂ C₁⁻¹)

A = G₂⁻¹ G₁
B = C₂ C₁⁻¹
AH = HB
```

这条等式的几何意义是两条路线到达同一个坐标系：

```text
路线一：相机1 ──H──→ 末端1 ──A──→ 末端2
路线二：相机1 ──B──→ 相机2 ──H──→ 末端2
```

相机和末端刚性连接，所以两次使用的 H 数值相同。

## 3 Eye to Hand 的推导

相机固定在外部，标定板固定在末端。此时：

- 待求固定关系变成 H = T^b_c，即相机 → 基座。
- 标定板相对于末端的位姿 T^e_t 不变。
- 标定板相对于基座会随手移动，不能再拿它作为不变量。

转换链改成：

```text
标定板 → 相机 → 基座 → 末端
T^e_t = T^e_b H T^c_t
```

为什么使用 T^e_b？因为到达基座后，还要继续转换到末端。机器人提供的是 T^b_e，需要取逆。

继续定义 G_i = T^b_ei，C_i = T^c_ti。两次得到同一个板相对于末端的位姿：

```text
G₁⁻¹ H C₁ = G₂⁻¹ H C₂
```

两边左乘 G₂，再右乘 C₁⁻¹：

```text
(G₂ G₁⁻¹) H = H (C₂ C₁⁻¹)

A = G₂ G₁⁻¹
B = C₂ C₁⁻¹
AH = HB
```

| 项目 | 眼在手上 | 眼在手外 |
| --- | --- | --- |
| 相机固定位置 | 末端 | 外部 |
| 标定板固定位置 | 外部 | 末端 |
| 用来列等式的不变量 | 板相对于基座 | 板相对于末端 |
| 未知 H | 相机 → 末端 | 相机 → 基座 |
| 上述 G_i 定义下的 A | G₂⁻¹G₁ | G₂G₁⁻¹ |

不要只记 AH = HB 的外形。两种情况下 H 和 A 的定义不同，混用会导致结果方向错误。

## 4 为什么先求旋转再求平移

原文用 θ_A、θ_X、θ_B 表示旋转矩阵，用 b_A、b_X、b_B 表示平移向量。θ 在这里不是单个角度；X 指的仍然是未知变换 H。以下统一用 R 和 t。

```text
A = [ R_A  t_A ]    H = [ R_H  t_H ]    B = [ R_B  t_B ]
    [  0    1  ]        [  0    1  ]        [  0    1  ]
```

按分块矩阵相乘：

```text
AH = [ R_A R_H   R_A t_H + t_A ]
     [    0             1      ]

HB = [ R_H R_B   R_H t_B + t_H ]
     [    0             1      ]
```

平移为什么也乘旋转？对点 p 连续应用两个变换：

```text
p'  = R_H p + t_H
p'' = R_A p' + t_A
    = R_A R_H p + R_A t_H + t_A
```

第一步产生的位移，也要随着第二步转换到新的坐标系。因此两个矩阵相等，给出：

```text
旋转：R_A R_H = R_H R_B
平移：R_A t_H + t_A = R_H t_B + t_H
```

第一条不包含 t_H，可以先求 R_H；将 R_H 代入第二条，剩下的未知量只有 t_H。

## 5 Park 方法求旋转

### 从旋转矩阵到旋转向量

旋转矩阵满足 R⁻¹ = Rᵀ，所以旋转方程可以右乘 R_Hᵀ：

```text
R_A = R_H R_B R_Hᵀ
```

这个关系表示：先换到 B 侧的表达坐标系，执行 R_B，再换回 A 侧，等价于直接执行 R_A。

```text
方向 v_A ─────────────────R_A────────────────→ 方向 v'_A
   │                                               ↑
   R_Hᵀ                                         R_H
   ↓                                               │
方向 v_B ─────────────────R_B────────────────→ 方向 v'_B
```

这里 A 侧、B 侧是为理解旋转共轭关系而使用的称呼，不是额外定义的机器人部件。

一次旋转可以由单位轴 u 和角度 θ 描述。旋转向量 φ = θu 的方向表示轴，长度表示角度，单位为弧度。它的三个分量不是欧拉角。

例如绕 Z 轴旋转 30°，φ = [0, 0, π/6]ᵀ。

同一根实体旋转轴，在不同坐标系中表达的方向可能不同，但实际旋转角度不变。因此若 α、β 分别对应 R_A、R_B，就有：

```text
α = R_H β
```

例如 R_H 把 B 侧 Z 方向映射到 A 侧 X 方向，那么 β = [0,0,π/6]ᵀ 对应 α = [π/6,0,0]ᵀ。

### 方括号与指数映射的含义

文档中的 [φ] 或 φ^ 表示由三维向量构造反对称矩阵：

```text
      [  0   −φ_z   φ_y ]
[φ] = [ φ_z    0   −φ_x ]
      [−φ_y   φ_x    0  ]

[φ]v = φ × v
```

旋转向量和旋转矩阵通过矩阵指数联系：R = exp([φ])。exp 是矩阵指数，不是对每个元素分别求指数。反方向通过矩阵对数和提取独立分量得到旋转向量。

利用旋转坐标变换性质：

```text
R_A = R_H R_B R_Hᵀ
exp([α]) = R_H exp([β]) R_Hᵀ
         = exp([R_H β])
```

采用一致的轴角分支时，得到 α = R_Hβ。指数映射不是全局一一对应，接近 180° 的轴符号等问题不能通过随意“消去 exp”处理。

### 多组向量如何求出旋转

每组相对运动提供 α_i = R_Hβ_i。测量有噪声，求使下面误差最小的合法旋转矩阵：

```text
min Σ ||α_i − R_H β_i||²
条件：R_HᵀR_H = I，det(R_H) = +1
```

可以把它理解成多对箭头对齐：同一个 R_H 要尽量把 β₁ 转到 α₁，把 β₂ 转到 α₂，依此类推。这是只有旋转的向量配准，不需要给这些向量额外估计平移。

一种常用的数值实现是 SVD：

```text
M = Σ α_i β_iᵀ
M = U Σ Vᵀ
D = diag(1, 1, det(UVᵀ))
R_H = U D Vᵀ
```

D 保证结果是旋转而不是镜像反射。不同资料对 M 的乘积顺序可能相反，对应的 U、V 使用顺序也会变化，不能混搭。

只有一根轴时，即使把箭头对齐，仍能绕它转动而不破坏对齐关系。因此要采集足够丰富、包含不平行旋转轴的运动，单纯增加同方向样本数量不能消除退化。

## 6 平移求解的详细展开

### 平移未知量究竟是什么

t_H 是 H 右上角的三维向量，表示来源坐标系原点在目标坐标系中的位置：

- 眼在手上：相机原点在末端坐标系中的位置。
- 眼在手外：相机原点在基座坐标系中的位置。

它是固定安装偏移，不是机器人某一次运动走了多远。A、B 的 t_A、t_B 才是相对运动变换里的平移分量。

### 将方程整理成三个未知数的线性问题

从分块矩阵乘法得到：

```text
R_A t_H + t_A = R_H t_B + t_H
```

左边是先执行 H 再执行 A 得到的总平移，右边是先执行 B 再执行 H 得到的总平移。两条变换链相同，所以总平移也必须相同。

把右侧 t_H 移到左侧，把左侧 t_A 移到右侧：

```text
R_A t_H − t_H = R_H t_B − t_A
(R_A − I)t_H = R_H t_B − t_A
```

这里 I 是 3×3 单位矩阵，因为 t_H = It_H。

令 C = R_A − I，d = R_Ht_B − t_A：

```text
Ct_H = d
```

C 已知，d 也已知，因为 R_H 已在上一阶段求出。未知 t_H = [x,y,z]ᵀ 只有三个数。

### 几何意义

R_A t_H − t_H 表示：把安装偏移向量旋转后，与原向量相比改变了多少。

```text
原安装偏移 t_H ──R_A──→ 旋转后的偏移 R_A t_H
             两者之差 = (R_A − I)t_H
```

机械臂转动时，离旋转轴有距离的相机原点会产生位移。机器人与相机观测到的运动差异，能反过来约束它们之间的安装偏移。

### 单组数据为什么不够

假设 R_A 绕 Z 轴旋转 90°：

```text
      [ 0 −1  0 ]                [−1 −1  0 ]
R_A = [ 1  0  0 ]    R_A − I = [ 1 −1  0 ]
      [ 0  0  1 ]                [ 0  0  0 ]
```

代入 t_H = [x,y,z]ᵀ：

```text
−x − y = d_x
 x − y = d_y
     0 = d_z
```

没有任何一条方程含 z！因此绕 Z 轴的一次旋转无法确定沿 Z 方向的安装偏移。

这是一般性质：任何三维旋转都有不变轴 u，满足 R_Au = u，所以 (R_A−I)u = 0。单组 C 一定奇异；没有旋转时 C 甚至全部为零。

原文写出 (CᵀC)⁻¹Cᵀd，需要补充前提：C 必须具有满列秩。单组 C 奇异时，CᵀC 同样奇异，左乘 Cᵀ 不能凭空补足信息。

### 用具体数字求一次平移

下面使用人为构造的理想数据演示。假设旋转标定已得到 R_H = I，所有平移单位为米。

第一组：A 绕 Z 轴转 90°，t_A = [0,0,0]ᵀ，t_B = [−0.3,0.1,0]ᵀ。因此 d₁ = R_Ht_B−t_A = [−0.3,0.1,0]ᵀ。

```text
−x − y = −0.3
 x − y =  0.1
     0 =  0
```

前两式相加：−2y = −0.2，所以 y = 0.1。
代入 x−y = 0.1，得到 x = 0.2。
z 仍然未知。

第二组：A 改为绕 X 轴转 90°，t_A = [0,0,0]ᵀ，t_B = [0,−0.15,0.05]ᵀ。此时：

```text
         [ 0  0  0 ]
R_A−I = [ 0 −1 −1 ]
         [ 0  1 −1 ]

     0 =  0
−y − z = −0.15
 y − z =  0.05
```

把第一组求得的 y = 0.1 代入，得到 z = 0.05，两条方程一致。

最终：

```text
t_H = [0.2, 0.1, 0.05]ᵀ 米
```

第一组确定 x、y，第二组补上 z。这就是不同旋转方向提供互补信息的具体例子。

### 有噪声时如何求解

实际数据通常不能让所有方程同时严格成立。把每组的三条方程纵向堆叠：

```text
C_total = [ R_A1 − I ]    d_total = [ R_H t_B1 − t_A1 ]
          [ R_A2 − I ]              [ R_H t_B2 − t_A2 ]
          [    …     ]              [         …       ]

C_total t_H ≈ d_total
```

有 m 组相对运动时，C_total 为 3m×3，d_total 为 3m 维，未知数仍只有三个。选择让总残差平方最小的 t_H：

```text
min ||C_total t_H − d_total||²
```

满列秩时，理论公式为：

```text
t_H = (C_totalᵀ C_total)⁻¹ C_totalᵀ d_total
```

数值实现优先使用最小二乘求解器，避免显式求逆。仍然要检查秩；求解器返回一个数值结果不代表运动数据足够约束真实解。

下面代码可直接验证前面的理想例子：

```python
import numpy as np

# 两组机器人相对旋转：先绕 Z，再绕 X，各旋转 90 度。
R_A1 = np.array([[0., -1., 0.], [1., 0., 0.], [0., 0., 1.]])
R_A2 = np.array([[1., 0., 0.], [0., 0., -1.], [0., 1., 0.]])

# 示例假设已经求得 R_H = I，且两组 t_A 都为零。
d1 = np.array([-0.3, 0.1, 0.])
d2 = np.array([0., -0.15, 0.05])

# 将两组方程堆叠成六条约束，求三个未知平移分量。
C = np.vstack([R_A1 - np.eye(3), R_A2 - np.eye(3)])
d = np.concatenate([d1, d2])
t_H, residuals, rank, singular_values = np.linalg.lstsq(C, d, rcond=None)

print("平移（米）：", t_H)  # [0.2, 0.1, 0.05]
print("约束矩阵秩：", rank)  # 3，三个平移分量都有约束
print("残差范数：", np.linalg.norm(C @ t_H - d))  # 接近 0
```

## 7 将旋转和平移组合成最终结果

```text
H = [ R_H  t_H ]
    [  0    1  ]
```

眼在手上时，物体从相机转换到基座需要当前机器人位姿：

```text
p_b = T^b_e H p_c
```

眼在手外时，H 已经直接连接相机和基座：

```text
p_b = H p_c
```

整个流程：多组机器人位姿和标定板观测 → 构造 A_i、B_i → 旋转向量对齐求 R_H → 堆叠平移方程求 t_H → 组装 H → 检查不同姿态下的标定一致性。

## 8 阅读时容易混淆的地方

- T 的上下标交换意味着转换方向反过来，对应矩阵求逆。
- 在 Rᵀ 中，上标 T 表示转置，与坐标变换矩阵的字母 T 不同。
- 眼在手上与眼在手外都能写成 AH = HB，但 H 的物理含义不同。
- 相机坐标系原点和工具坐标系原点由建模与设备约定确定，标定必须与实际使用的坐标定义一致。
- 旋转向量方向是旋转轴，长度是旋转角，不是三次依次执行的欧拉角。
- 方向向量换坐标只使用旋转；点的位置换坐标通常还需要平移。
- t_H 是固定安装偏移，t_A、t_B 是运动变换中的平移分量。
- 单组旋转无法确定沿自身旋转轴方向的安装偏移，多方向运动用来补足约束。
- 平移单位必须一致，不能把毫米和米直接混合。
- 相对运动的配对顺序必须一致；只把 A 取逆而不对应处理 B，会破坏原等式。

## 9 讨论补充：F 和 T 是什么关系？

**F 表示坐标系，T 表示两个坐标系之间的变换矩阵。**

| 符号 | 含义 |
| --- | --- |
| F_b | 固定在底座上的坐标系 |
| F_e | 固定在末端／夹爪上的坐标系 |
| F_c | 相机坐标系 |
| F_t | 标定板坐标系 |

每个 F 都可以想象成一个原点和三根 xyz 轴。T 则负责换算同一个点在这些坐标系中的坐标。

例如：

$$
\begin{bmatrix}p_e\\1\end{bmatrix}
=T^e_c\begin{bmatrix}p_c\\1\end{bmatrix}
$$

这里下标 c 是来源，上标 e 是目标，表示相机坐标 → 夹爪坐标。点本身没有变，只是描述它的坐标系变了。

T^e_c 内部的 R^e_c 描述相机三根坐标轴在夹爪系中的方向，t^e_c 描述相机原点在夹爪系中的位置。

注意：F_t 的下标 t 是 target（标定板）；小写平移向量 t 是 translation。这两个 t 含义不同。

## 10 讨论补充：为什么两次拍照的矩阵都能写成 H？

眼在手上的推导中有：

$$
T^{e2}_{e1}T^{e1}_{c1}=T^{e2}_{c2}T^{c2}_{c1}
$$

其中：

- e1、c1 是第一次拍照时的末端和相机坐标系。
- e2、c2 是第二次拍照时的末端和相机坐标系。
- T^{e1}_{c1} 与 T^{e2}_{c2} 都描述相机相对于夹爪的安装关系。

相机通过刚性支架固定在夹爪上，夹爪运动时，相机也跟着一起运动。从夹爪自身的视角看，相机的位置和朝向都没有变，因此两次变换的数值相同：

$$
T^{e1}_{c1}=T^{e2}_{c2}=T^e_c=H
$$

于是：

$$
\underbrace{T^{e2}_{e1}}_A H
=H\underbrace{T^{c2}_{c1}}_B
$$

**不是所有矩阵都变成 H，而是两个“相机相对于夹爪”的矩阵相等，所以都用 H 表示。** 前提是相机与夹爪刚性固定，采集过程中没有改变安装关系。

## 11 讨论补充：相机到底利用标定板的什么数据？

核心是同一批特征点的两组对应坐标：**它们在标定板上的实际三维坐标，以及它们在图像中的二维像素坐标。**

### 11.1 图像里检测到的是像素坐标

以棋盘格为例，程序检测黑白格交界的内角点：

```text
角点 1：(u₁, v₁)
角点 2：(u₂, v₂)
角点 3：(u₃, v₃)
……
```

u、v 是图像上的横纵位置，单位是像素，尚不是相机坐标系中的三维位置。

### 11.2 标定板的实际尺寸提供三维坐标

例如格子边长为 20 毫米，以一个内角点为原点，在板面上建立 x、y 轴：

```text
角点 1：( 0,  0, 0) 毫米
角点 2：(20,  0, 0) 毫米
角点 3：(40,  0, 0) 毫米
下一行：( 0, 20, 0) 毫米
……
```

所有角点都位于板面，所以在标定板坐标系中 z = 0。这不代表它们到相机的距离为零。

需要保证实际角点与图像角点一一对应，编号、原点和轴方向在各次采集中一致。板的尺寸决定估计平移的尺度：以毫米输入板坐标，得到的平移也以毫米表示。

### 11.3 结合内参，求标定板相对于相机的位姿

```text
标定板角点的实际三维坐标 ─┐
图像里对应角点的像素坐标 ─┼→ 位姿估计（PnP）→ Rᶜₜ、tᶜₜ
相机内参与畸变参数       ─┘
```

组合得到：

$$
T^c_t=\begin{bmatrix}R^c_t&t^c_t\\0\quad0\quad0&1\end{bmatrix}
$$

它描述标定板原点在相机系中的位置，以及标定板坐标轴在相机系中的方向。这一步利用已知尺寸恢复位姿，并不要求使用深度相机。

### 11.4 一张图与多张图分别起什么作用？

- 一张图里的多个角点，结合内参和板的实际尺寸，用来估计这次标定板相对于相机的位姿 T^c_t；实际还要处理噪声、平面位姿歧义等情况。
- 多次不同姿态的拍摄，配合对应的机器人末端位姿，用来求固定的手眼关系 H。

眼在手上，每次采集需要配对保存：

| 数据 | 来源 | 含义 |
| --- | --- | --- |
| T^b_ei | 机器人位姿接口，或关节角度结合正运动学 | 第 i 次采集时末端在底座中的位姿 |
| T^ci_t | 第 i 张标定板图像的位姿估计 | 标定板在该次相机坐标系中的位姿 |

机器人位姿必须与照片对应同一次采集，且始终使用同一末端定义，例如不能混用法兰坐标系和带工具偏置的工具坐标系。

## 12 讨论补充：眼在手上最终是求标定板到基座吗？

**眼在手上最终要求的是相机到夹爪的固定变换 H = T^e_c，包括它的 R 和 t。**

$$
\boxed{H=T^e_c=\begin{bmatrix}R^e_c&t^e_c\\0\quad0\quad0&1\end{bmatrix}}
$$

| 变换 | 坐标换算方向 | 在标定中的角色 |
| --- | --- | --- |
| T^b_e | 夹爪 → 底座 | 机器人提供，每次姿态可能不同 |
| T^c_t | 标定板 → 相机 | 图像位姿估计提供，每次姿态可能不同 |
| T^e_c = H | 相机 → 夹爪 | 固定但未知，是标定目标 |
| T^b_t | 标定板 → 底座 | 固定但可未知，用其不变性建立方程 |

关系是：

$$
T^b_t=T^b_e\,H\,T^c_t
$$

标定板和基座都固定不动，所以不同拍照姿态算出的 T^b_t 应相同。利用这个条件，消去未知但固定的 T^b_t，得到 AH = HB 并求 H。

如果口头说“标定板到基座”，按本文约定应写成 T^b_t。不要仅写 `Ttb` 而省略上下标或转换方向；反向的 T^t_b 是它的逆矩阵。

求出 H 后，也可以用上式计算标定板在底座中的位姿，但这不是眼在手上标定的主要未知安装关系。

### 标定完成后如何用于物体定位？

假设视觉系统已经得到某个物体点在相机系中的三维坐标 p_c，那么：

$$
\begin{bmatrix}p_b\\1\end{bmatrix}
=T^b_e\,H\begin{bmatrix}p_c\\1\end{bmatrix}
$$

```text
物体点的相机坐标
      ↓ 标定得到的 H = Tᵉ_c
物体点的夹爪坐标
      ↓ 当前机器人位姿 Tᵇ_e
物体点的底座坐标
```

标定板此时可以拿走。只要相机与夹爪的安装关系没变，H 仍然可用；机器人运动时，需要更新的是 T^b_e。

注意：手眼矩阵处理三维坐标变换，不能单靠它把一个二维像素直接变成三维位置。实际物体定位还需要深度、已知物体几何或其他三维定位信息。

## 13 学习与验证顺序

1. 画清四套坐标系，说明哪个关系固定、哪个随运动变化。
2. 说清每次采集的 T^b_e 和 T^c_t 如何获得，以及未知 H 的物理意义。
3. 从固定标定板的条件出发，独立推导一次 AH = HB，核对矩阵左右乘顺序。
4. 把方程分成旋转和平移，再理解 Park 方法与多组最小二乘求解。
5. 用人为设定的 H 生成一致的模拟观测，恢复 H，与标准答案比较；再加入噪声分析误差。
6. 用实际或仿真数据验证：各姿态算出的 T^b_ei H T^ci_t 是否接近同一个位姿？未参与求解的数据是否也满足？
7. 沿同样步骤学习眼在手外，重新核对 H 和 A 的定义。

得到一个矩阵不等于标定成功。需要检查位姿配对、单位、坐标系方向、运动丰富程度，并使用独立数据验证。

## 14 我的理解：手眼标定的目的，以及标定后怎么用

> 我现在的理解是：标定先求出相机与夹爪之间缺少的那一段变换 H。知道 H 后，就可以把那几个 T 按坐标关系连乘，得到标定板或物体在底座坐标系中的完整位姿，再从结果里提取 R 和 t，知道它朝哪里、在哪里。

这段理解针对眼在手上、且视觉已经给出目标完整三维位姿的情况。下面把“求 H”“验证 H”“使用 H”分开记录。

### 14.1 为什么标定板到基座的变换可以事先不知道？

标定时已知机器人提供的 T^b_ei，以及从标定板图像估计的 T^ci_t；未知的是 H。标定板与基座固定不动，所以它们之间的变换 K = T^b_t 虽然具体数值未知，但每次都是同一个值：

$$
T^b_{e_1}H T^{c_1}_t=K,
\qquad
T^b_{e_2}H T^{c_2}_t=K
$$

因此两边可以直接相等：

$$
T^b_{e_1}H T^{c_1}_t=T^b_{e_2}H T^{c_2}_t
$$

K 就被消掉了，继续整理得到 AH = HB。

可以类比 x+2=k、2x−1=k：不用先知道 k，就能利用 x+2=2x−1 求出 x。手眼标定中则需要多组具有足够不同旋转方向的观测来充分约束 H。

**“不知道数值”和“关系不变”不是一回事。正是关系不变，才允许我们消掉这个未知量。** 若标定板相对于基座在采集中移动，上述不变条件就不成立。

### 14.2 求出 H 后，原来的连乘公式有什么用？

标定的核心结果是：

$$
H=T^e_c=\begin{bmatrix}R_H&t_H\\0\quad0\quad0&1\end{bmatrix}
$$

把它代回每组数据：

$$
K_i=T^b_{e_i}H T^{c_i}_t
$$

每个 K_i 都是估计出的标定板底座位姿。因为板没有动，各次结果的位置与朝向应接近一致。再用未参与求解的新姿态检查一致性，才能判断结果是否可靠。

所以，写出公式还不等于完成标定；求出 H 并验证精度后，才进入实际使用。允许多大误差要由具体任务的精度要求决定。

### 14.3 实际使用：把标定板换成待抓物体

设 o 表示物体，视觉算法已经得到物体在相机中的完整位姿 T^c_o。此时：

$$
\boxed{T^b_o=T^b_e\,H\,T^c_o}
$$

从右向左理解：

```text
物体坐标 → 相机坐标 → 夹爪坐标 → 底座坐标
          Tᶜ_o       H=Tᵉ_c      Tᵇ_e
```

| 量 | 使用时从哪里获得？ | 是否变化？ |
| --- | --- | --- |
| H = T^e_c | 保存的手眼标定结果 | 相机与夹爪安装关系不变时固定 |
| T^b_e | 与图像对应的机器人末端位姿 | 机器人运动时变化 |
| T^c_o | 视觉算法估计的物体位姿 | 相机或物体运动时可能变化 |
| T^b_o | 三者连乘得到 | 是需要的物体底座位姿 |

标定板在完成标定与验证后可以拿走。实际使用时不需要每次重新求 H，但必须使用与图像对应的机器人位姿，并保持单位和末端坐标系定义一致。

### 14.4 从连乘结果中提取 R 和 t

$$
T^b_o=\begin{bmatrix}R&t\\0\quad0\quad0&1\end{bmatrix}
$$

```python
# 三个输入都是 4×4 齐次变换矩阵。
T_base_object = T_base_end @ H @ T_camera_object

R = T_base_object[:3, :3]  # 左上角 3×3：物体相对于底座的朝向
t = T_base_object[:3, 3]   # 第四列前三项：物体原点在底座中的位置
```

Python 下标从 0 开始，`:3` 取下标 0、1、2，不包含 3；列下标 `3` 就是第四列。

讨论时口头说“连乘得到 Ttb”，如果对象是标定板，准确写法为 T^b_t；如果对象是实际物体，则写 T^b_o。不要省略坐标转换方向。

### 14.5 如果视觉只给一个点，能不能提取 R？

不能。若视觉只给物体某个点的三维坐标 p_c，则计算：

$$
\begin{bmatrix}p_b\\1\end{bmatrix}
=T^b_eH\begin{bmatrix}p_c\\1\end{bmatrix}
$$

```python
p_camera = np.array([0.10, 0.05, 0.40, 1.0])
p_base = T_base_end @ H @ p_camera
position = p_base[:3]
```

结果是一个点的坐标，而不是物体的 4×4 位姿矩阵。**一个点本身没有朝向，不能由这次坐标换算得到物体的 R。** 只有二维像素时，还需深度、已知物体几何等信息才能恢复三维位置。

### 14.6 物体位姿算出来后，还需要什么？

提取出的 R、t 描述的是物体，不自动等于夹爪应该到达的目标位姿。抓取还要确定夹爪相对于物体的朝向与偏移，并完成逆运动学、碰撞检查和轨迹规划。

```text
标定阶段：多组观测 → 求 H → 验证精度 → 保存 H

应用阶段：拍照 → 估计物体三维位置／位姿
                   ↓
           用当前机器人位姿和 H 换算到底座系
                   ↓
           确定夹爪目标抓取位姿
                   ↓
           逆运动学、轨迹规划与执行
```

**记住目的：标定求 H；使用时把各段变换连起来，把视觉结果转换为机器人能够使用的底座坐标。**
